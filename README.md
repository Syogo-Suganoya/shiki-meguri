# シキめぐり

冠婚葬祭レンタル × 移動エージェント。

衣装レンタルの「借りるまで」しかなかった体験を、**試着 → 受取地最適化 → 当日の逆算動線 → 返却**まで
一気通貫でエージェントが仕切る。金銭が動く操作だけは必ず本人の同意ゲートを通す。

- 仕様の背景 → [設計書.md](設計書.md)
- 開発手順・コードの決まりごと → [CONTRIBUTING.md](CONTRIBUTING.md)
- Google Cloud へのデプロイ → [DEPLOY.md](DEPLOY.md)

## 動かす

APIキーは不要。未設定のうちは全ての外部サービスが mock で動き、デモは最後まで通る。
データは同梱の Firestore エミュレータに入るので、GCP に繋がなくてよい。

```bash
docker compose up api
```

ブラウザで <http://localhost:8080/ui/> を開き、チャット欄に「明日16時、品川の結婚式にお呼ばれ」と送る
（右上の「シナリオ開始」でデモデータから始めることもできる）。

| 画面 | 何が見えるか |
|---|---|
| 0. チャット | 自前のチャット欄。「明日16時、品川の結婚式にお呼ばれ」から候補提示・承認・返却まで会話で完結する |
| 1. 試着 | パーソナルカラー × ドレスコードでの絞り込み（提案まで） |
| 2. 手配 | 自宅配送／店舗／ロッカーを**当日の動線コミ**で比較した表 |
| 3. 同意ゲート | 金額内訳と承認／却下。承認するまで予約 API は呼ばれない |
| 4. 動線 | 開式からの逆算タイムライン。遅延を注入 → 再計算（自律実行） |
| 5. 返却監視 | 期限との突合、延長の起案（提案まで） |
| 6. 式ムービー工房 | 写真 → 補正 → 動画化 → BGM（GMI Cloud）。第三者の写り込み同意と制作費の承認を通す |
| 7. 監査ログ | 全エージェントの判断根拠・同意記録・画像破棄証跡 |

## アーキテクチャ

![アーキテクチャ図](docs/architecture.png)

チャットは外部メッセージング基盤を使わず自前で持つため、慶弔という繊細な情報が
第三者のサーバーを経由しない。**通知もアプリ内で完結する**（設計判断）。遅延の再計算や
返却期限の警告といったエージェント起点の発言は、利用者の操作を待たずに画面へ届く。
端末へのプッシュ（Web Push / OS 通知）は対象外。

定期実行（Cloud Scheduler）が遅延の再計算・返却期限の監視・TTL 超過の削除をまとめて回す。

## エージェントの自律性

設計書 §4 の境界は、コードの分かれ方と一致している。

| エージェント | 自律性 | 実装 |
|---|---|---|
| 試着 | 提案まで | `agents/tryon.py` |
| 手配 | **金銭確定は本人同意必須** | `agents/arrange.py`（`propose` と `decide` が分離） |
| 動線 | 再計算・通知は自律実行 | `agents/route.py` |
| 返却監視 | 提案まで | `agents/monitor.py` |
| 式ムービー工房 | 提案まで（**生成費も本人同意必須**） | `agents/movie.py` |

## ガバナンス（設計書 §7）

1. **試着画像の即時破棄** — 顔・全身画像は結果生成と同時に破棄し、破棄時刻を監査ログに残す。弔事は生成物の保持もさらに短縮（`MOURNING_IMAGE_TTL_SECONDS`）
2. **慶弔情報の最小化** — 「誰の式か」「誰が亡くなったか」を保持するフィールドがそもそも存在しない。日時・会場・服装区分だけで全機能が成立する（テストで検証）
3. **同意ゲート** — `AGENT_SPEND_LIMIT_YEN=0` が既定。エージェントは 1 円も自律確定できない
4. **TTL** — `events` は式終了 + 7 日で削除。監査ログは追記専用で独立して残る

## 式ムービー工房（設計書 §11 追加案）

結婚式のプロフィールムービーを GMI Cloud で自動制作するアドオン。
衣装（本体）と同じ「式の準備の外注コスト」を下げる位置づけ。

| 工程 | 使うモデル |
|---|---|
| 写真の補正・色調統一 | `bria-fibo-restore` / `bria-fibo-restyle` |
| 静止画の動画化 | `Kling-Image2Video-V2.1-Pro` |
| オリジナルBGM | `minimax-music-2.5` |

ガバナンスは本体と同じ考え方に揃えている。

1. **第三者の写り込み同意** — 友人・家族が写る写真は、掲載可否を確認するまで生成に進めない
2. **AI生成の明示** — 生成物に `AI生成` の表示を持たせ、監査ログにも残す
3. **制作費の同意ゲート** — 生成は課金を伴うため、起案 → 本人承認 → 実行
4. **式後の自動削除** — 素材も生成物も `events` の中に持つので、本体の TTL で一緒に消える
